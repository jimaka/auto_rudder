### 1.4 开发原则

1. **纯算法层**：所有模块不含任何硬件 IO（GPIO/CAN/UART/EEPROM），传感器输入与舵机输出一律通过函数参数传递；EEPROM 读写通过 `std::function` 注入。这是单元测试与 HIL 仿真可行的前提。
2. **header-only + C++17 + 零第三方依赖**：便于直接嵌入 ECU 工程，避免交叉编译链接问题。
3. **确定性执行**：主循环内禁止动态内存分配（`ManeuverSequencer::setLegs` 等配置类接口除外）、禁止异常、禁止阻塞调用，保证 50 Hz（20 ms）周期的最坏执行时间可控。
4. **单位与约定统一**：角度一律用 **度（deg）**，转向率 deg/s，船速 kn，时间 s；航向误差恒定义为 `ref − act` 并归一化到 (−180°, 180°]；舵角右舵为正。
5. **可追溯**：每个函数/常量注释标注对应设计文档章节号（如 `§3.3`），设计变更时可反向检索受影响代码。

## 3. PD 航向控制器开发

### 3.1 设计依据

设计文档 §3.2（控制律与角度归一化）、§3.3（输出限幅）、§3.7（抗噪与死区）。实现文件：`control/include/pd_controller.hpp`，前置依赖 `angle_utils.hpp`。

### 3.2 开发任务拆解

PD 控制器虽然公式简单，但工程实现要点集中在"公式之外"的 6 个开发点，缺一不可：

| 开发点 | 设计依据 | 一句话要求 |
|--------|----------|-----------|
| DP-1 角度归一化误差 | §3.2 | 误差必须经 atan2 等价归一化到 (−180°, 180°] |
| DP-2 微分低通滤波 | §3.2/§3.7 | 差分微分必须带一阶低通，τ = 0.2 s |
| DP-3 误差死区 | §3.3/§3.7 | \|e\| < 0.3° 时输出 0，减少操舵频次 |
| DP-4 舵角限幅 | §3.3 | 输出饱和 ±35° |
| DP-5 舵速限幅 | §3.3 | 相邻周期输出变化 ≤ 10°/s × dt |
| DP-6 输出量化 | §3.7 | 目标舵角量化到 0.1°（12-bit 舵角分辨率） |

### 3.3 处理链与执行顺序

**执行顺序是本模块最重要的实现约束**：死区判断最先（直接短路返回），量化最后；舵速限幅必须在舵角限幅之后，否则限幅截断会破坏速率约束。

```mermaid
graph TD
    IN["输入 ψ_ref, ψ_act"] --> E["DP-1 误差 e = angleDiffDeg(ψ_ref, ψ_act)"]
    E --> DZ{"DP-3 死区判断<br/>abs(e) < 0.3° ?"}
    DZ -->|是| ZERO["输出 0（量化后返回）<br/>同步 prevErr 保持状态平滑"]
    DZ -->|否| DER["DP-2 微分：derivRaw = (e − e_prev)/dt<br/>低通：deriv = α·derivRaw + (1−α)·deriv_prev"]
    DER --> PD["控制律 δ_raw = Kp·e + Kd·deriv"]
    PD --> SAT["DP-4 舵角限幅 clip(δ_raw, ±35°)"]
    SAT --> RATE["DP-5 舵速限幅<br/>abs(δ − δ_prev) ≤ 10°/s · dt"]
    RATE --> Q["DP-6 量化 round(δ/0.1)·0.1"]
    Q --> ST["更新状态 prevErr/prevDeriv/prevOut"]
    ST --> OUT["输出目标舵角 δ"]
```

### 3.4 各开发点实现细节

#### DP-1 角度归一化误差

$$
e = \text{atan2}(\sin(\psi_{\text{ref}}-\psi),\ \cos(\psi_{\text{ref}}-\psi))
$$

工程实现不必调用三角函数，用 while 折叠等价实现（`angle_utils.hpp` 的 `normalizeAngleDeg`）：结果落在 **(−180°, 180°]**，注意区间是左开右闭——`normalizeAngleDeg(180)` 必须返回 +180 而不是 −180，边界条件用 `a <= -180` 判断实现。

典型错误示例：ψ_ref = 1°、ψ_act = 359°，直接相减得 −358°，归一化后应为 **+2°**（右转 2° 而不是左转 358°）。

#### DP-2 微分低通滤波

$$
\dot e_k = \alpha\cdot\frac{e_k - e_{k-1}}{\Delta t} + (1-\alpha)\cdot\dot e_{k-1},\qquad
\alpha = \frac{1}{1+\tau/\Delta t}
$$

- 取 τ = 0.2 s、dt = 0.02 s 时 α ≈ 0.0909，即新样本权重约 9%，等效截止频率约 0.8 Hz，可压制 AHRS/GNSS 高频噪声。
- **首拍处理**：第一拍没有 e_{k−1}，若直接差分会产生一次 e/dt 量级的微分冲击（e = 30° 时冲击达 1500°/s）。实现上用 `first_` 标志令首拍 `derivRaw = 0`。
- **微分对象的选择**：本实现对误差 e 微分。若 ψ_ref 会被上层频繁阶跃修改（如机动序列切段），对 e 微分会引入"设定值踢"（derivative kick）；缓解手段是切换目标航向时调用 `reset()`，或后续版本改为对测量值 −ψ 微分。

#### DP-3 误差死区

- 死区内输出 0 而不是"保持上一输出"，语义为"回中"；死区内仍要更新 `prevErr_`，否则退出死区的第一拍会把死区期间积累的误差变化一次性算进微分。
- **死区边界抖动**：e 在 0.3° 附近来回穿越时输出在 0 与非 0 间跳变。当前实现依靠舵速限幅（DP-5）天然抑制跳变幅度；若海试发现操舵频次超标（> 6 次/分钟），加迟滞（如 0.3° 进入 / 0.5° 退出）。

#### DP-4 / DP-5 双重限幅

$$
\delta = \mathrm{clip}(\delta_{\text{raw}},\ \pm\delta_{\max}),\qquad
|\delta_k - \delta_{k-1}| \le \dot\delta_{\max}\cdot\Delta t
$$

- 顺序固定为 **先幅值后速率**。dt = 0.02 s 时单周期最大变化量 10 × 0.02 = 0.2°，即从 0 打到 35° 满舵至少需要 3.5 s，与舵机物理能力一致。
- 舵速限幅基于 `prevOut_` 递推，因此 `reset()` 后第一拍从 0 开始爬升；上电/切入自动模式时舵不在中位的问题已解决（P11 整改已落地）：切入 AUTO_HEADING 的首拍以实际舵角反馈调 `initBaseline()` 初始化舵速限幅基准，舵令不再从 0° 爬升（§9.8 EnterAutoHeadingSeedsRudderBaseline 回归用例）。

#### DP-6 输出量化

`round(v / 0.1) * 0.1`。量化必须放在处理链最后，否则量化误差会被后级放大。量化本身也兼具消除极小抖动输出的作用。

## 4. 增益调度开发

### 4.1 设计依据

设计文档 §3.5（PD 参数整定示例表）、§3.6（增益调度）、§3.10.4（按船速分段的 ζ*/ωn* 表）。实现文件：`control/include/gain_schedule.hpp`。

### 4.2 算法拆解

增益调度是一张 **船速 × 海况 → (Kp, Kd)** 的二维查表，速度维按段中点锚定线性插值（P5 整改，消除段切换跳变）。物理动因：船速越高、海况越差，等效模型增益 K 越大且噪声越强，需要越保守的控制增益。

```mermaid
graph TD
    IN["输入 speedKn, seaState"] --> CL["海况限幅 clamp(seaState, 0, 3)"]
    CL --> FILT["按 seaState 过滤该海况速度段<br/>表为空 → 默认 Kp=1.0, Kd=0.5"]
    FILT --> MID["各段中点 m_i = (speedMin+speedMax)/2<br/>名义增益锚在中点"]
    MID --> CMP{"v 与中点比较"}
    CMP -->|"v ≤ m_0"| FIRST["取首段名义值"]
    CMP -->|"v ≥ m_last"| LAST["取末段名义值"]
    CMP -->|"m_i ≤ v ≤ m_i+1"| INTERP["相邻中点间线性插值<br/>Kp/Kd 按同一比例 f"]
    FIRST --> RET["返回 Kp/Kd"]
    LAST --> RET
    INTERP --> RET
```

### 4.3 调度表数据结构与默认内容

```cpp
struct GainPoint {
    double speedMin, speedMax;  // [speedMin, speedMax) kn
    int    seaState;            // 0..3
    double Kp, Kd;
};
```

默认表共 14 条记录（4 个速度段 × 海况分组），与设计文档 §3.5 示例表和 §3.10.4 分段一致：

| 船速区间 (kn) | 海况 0~1 | 海况 2~3 |
|---------------|----------|----------|
| [0, 4) | Kp=2.0, Kd=0.8 | —（同 0~1，低速不区分） |
| [4, 10) | Kp=1.5, Kd=0.6 | Kp=1.0, Kd=0.4 |
| [10, 18) | Kp=1.2, Kd=0.5 | Kp=0.9, Kd=0.4 |
| [18, 25) | Kp=1.0, Kd=0.4 | Kp=0.7, Kd=0.3 |

### 4.4 实现细节与易错点

1. **段中点锚定插值（P5 整改后语义）**：名义增益锚在每段中点 m_i = (speedMin+speedMax)/2；v 落在相邻中点 [m_i, m_{i+1}] 间时按同一比例 f 对 Kp/Kd 线性插值——中点处恰取名义值（NominalAtMidpoint），跨中点交界连续（InterpolationContinuityAtBoundary）。段边界（如 10.0 kn）只是普通插值点，不再是跳变点。
2. **速度超出中点覆盖范围**：v ≤ 首段中点（2 kn）取首段名义值，v ≥ 末段中点（21.5 kn）取末段名义值——等价于"两端外推为常值"，保证高速仍返回最保守增益而不是失败。
3. **海况输入防御**：外部海况估计可能给出越界值，入口 `clamp(0, 3)`。
4. **段切换跳变已消除（§10.5-P5 已关闭，P5 整改已落地）**：旧实现为阶跃查表，船速穿越段边界时 Kp 从 1.5 跳到 1.2，经 PD 输出会产生一次小的舵角阶跃；现按当时的方向一（速度维相邻段线性插值）实现，跳变源头消除，方向二（查表结果加一阶低通 / 斜坡限速）未采用亦不需要。
5. **自定义表替换**：整表可由标定结果替换（配合 `param_store` 的区块 D），替换时必须校验"每个海况分组的速度段完整覆盖 [0, 25) 且无重叠"，建议提供 `validate()` 工具函数。

### 4.5 增益切换与 PD 的衔接

查表结果每周期写入 PD 参数。由于 `PdController::setParams()` 会 `reset()` 内部状态（§3.5 注意事项），衔接方式必须是下列之一：

- **方案 A（推荐）**：给 `PdController` 增加 `setGains(Kp, Kd)` 轻量接口，只改增益不清状态；
- 方案 B：仅当增益变化超过阈值（如 1%）时才调用 `setParams`，并接受一次状态清零。

已按方案 A 落地（P1 整改，§10.5-P1 已关闭）：`PdController` 提供 `setGains(Kp, Kd)` 与 `setDt(dt)` 轻量接口，只改增益/采样周期、不清状态；`headingControlStep` 每拍经它们转发调参器输出增益，主循环不再调 `setParams`。

## 5. Nomoto 模型辨识开发

### 5.1 设计依据

设计文档 §3.4（Nomoto 一阶模型）、§3.9.4（Z 形试验离线辨识）、§3.10.3（RLS 在线辨识）。实现文件：`control/include/nomoto_identifier.hpp`。

### 5.2 模型离散化推导

连续模型 $T\dot r + r = K\delta$，用后向差分 $\dot r \approx (r_k - r_{k-1})/\Delta t$ 离散化：

$$
r_k = K\delta_k - \frac{T}{\Delta t}(r_k - r_{k-1})
$$

整理为线性回归 $y_k = \phi_k^T\theta$：

$$
\phi_k = \left[\delta_k,\ -\frac{r_k - r_{k-1}}{\Delta t}\right]^T,\quad
y_k = r_k,\quad
\theta = [K,\ T]^T
$$

该形式的价值在于：**K、T 同时以线性参数出现**，离线最小二乘与在线 RLS 共用同一套回归量构造代码。

### 5.3 两条辨识路线

| 项 | 路线 A：离线批量 LS（§3.9.4） | 路线 B：在线 RLS（§3.10.3） |
|----|------------------------------|----------------------------|
| 使用场景 | 装船标定、海试 Z 形试验 | 运行中持续跟踪 K/T 慢变 |
| 激励来源 | 人工 Z 形试验（±10°/10°，3~5 循环） | 正常操舵自然激励 |
| 算法 | $\hat\theta = (\Phi^T\Phi)^{-1}\Phi^T y$ | 带遗忘因子 λ=0.98 的递推 LS |
| 载体 | PC 离线脚本（M2 交付的辨识工具） | ECU 内 `NomotoIdentifier` |
| 验收 | 拟合残差 RMS < 5% · r_max | 仿真数据上收敛误差 < 5% |

两条路线共享回归量构造，离线工具建议直接复用 `NomotoIdentifier`（λ 置 1.0、P0 足够大即可等效批量 LS 的递推形式）。

### 5.4 RLS 递推实现

$$
K_k = \frac{P_{k-1}\phi_k}{\lambda + \phi_k^T P_{k-1}\phi_k},\qquad
\hat\theta_k = \hat\theta_{k-1} + K_k\,(y_k - \phi_k^T\hat\theta_{k-1}),\qquad
P_k = \frac{1}{\lambda}\left(P_{k-1} - K_k\phi_k^T P_{k-1}\right)
$$

R1 深化（自降频接口）：`update(δ, r, dtNow)` 可由调用方按任意频率调用，模块内部累计满 `Params.beatSec`（默认 1.0 s）才做一次 RLS 拍；差分 Δt 由模块自测（两次 RLS 拍的真实间隔），与调用频率无关。旧设计把"50 Hz × 1 s"的降频约定放在调用方（计数器 + 外部改写 `Params.dt` 为 1.0），调用频率一变差分即静默出错——该语义陷阱已随 `Params.dt` 字段一并删除。

```mermaid
graph TD
    IN["输入 δ, r, dtNow（任意频率调用）"] --> GATE{"自降频判断<br/>累计 elapsed ≥ beatSec ?"}
    GATE -->|否| ACC["仅累计时间<br/>返回 false"]
    GATE -->|是| BEAT["做 RLS 拍：自测拍长 Δt = elapsed<br/>点采样：取拍时刻样本"]
    BEAT --> EXC{"激励判断<br/>abs(δ) > 3° 且<br/>(abs(r) > 0.5°/s 或 abs(dr) > 0.2°/s²) ?"}
    EXC -->|否| SKIP["跳过更新<br/>记录拍时刻 prevR，返回 false"]
    EXC -->|是| PHI["构造回归量<br/>dr = (r − prevR)/Δt，φ = [δ, −dr]"]
    PHI --> GAIN["增益 K_k = P·φ / (λ + φᵀPφ)<br/>分母 < 1e-12 时放弃本次更新"]
    GAIN --> UPD["残差 err = r − φᵀθ<br/>θ ← θ + K_k·err"]
    UPD --> COV["协方差 P ← (P − K_k·φᵀP)/λ"]
    COV --> OUT["输出 K = θ[0], T = θ[1]"]
```

### 5.5 实现细节与易错点

1. **激励门限是数值稳定的生命线**（|δ| > 3° 且 |r| > 0.5°/s）。直航时 δ、r 均近零，φ ≈ 0，若仍更新则 P 阵按 1/λ 每步放大 2%（"协方差爆炸"），一旦重新出现激励，θ 会剧烈跳变。无激励时**必须完全跳过 P 与 θ 的更新**。
2. **首拍差分**：第一个 RLS 拍无 r_{k−1}，令 dr = 0。R1 自降频后 `prevR_` 只在 RLS 拍时刻更新（非拍调用不写），差分恒跨"两次 RLS 拍"，Δt 取两拍真实间隔——长时间未激励后重新进入激励段时差分仍连续，无需额外处理。另注意被拒绝的拍（NaN/超限/非法 dtNow）不写 `prevR_`，否则毛刺会成为下一拍差分锚点（P11）。
3. **分母保护**：`λ + φᵀPφ` 理论上恒正，但浮点异常输入（NaN/Inf 传感器值）可能破坏该性质，实现中做了 `< 1e-12` 防御；工程上还应在入口对 δ、r 做范围检查（|δ| ≤ 35°、|r| ≤ 30°/s，超限丢弃）。
4. **物理合理性检查**（已实装，P6 整改）：`valid()` 门限 K ∈ (0, 2]（1/s 量级）、T ∈ [1, 60] s（非有限值一并拒绝）；越界说明数据质量差——辨识快照 `valid=false` 时调参器（周期评估与 `establishBaseline`）不会把该结果送入层 2 极点配置（§10.5-P6 已关闭）。
5. **调用节拍（R1 自降频）**：设计文档 §3.10.3 规定辨识每 **1 s** 更新一次（降低 ECU 负担并保证差分信噪比）。R1 深化后该节拍由模块自维护：主循环按 50 Hz 直接调 `update(δ, r, dtNow)`，内部累计满 `Params.beatSec`（默认 1.0 s）才做一次 RLS 拍，差分 Δt 自测（两次 RLS 拍的真实间隔），调用频率变化不影响正确性；`Params.dt` 字段已删除，不再需要调用方改写（§10.5-P3 由 R1 根治）。
6. **单位一致性**：全链路用度（deg、deg/s），则辨识出的 K 单位为 (deg/s)/deg = 1/s，与弧度制数值相同，可直接用于极点配置公式。

### 5.6 收敛性单测方案

### 6.3 层 2：极点配置

由期望闭环 ζ*、ωn* 与辨识值反推（设计文档 §3.10.4）：

$$
K_p = \frac{(\omega_n^\ast)^2\, \hat T}{\hat K},\qquad
K_d = \frac{2\zeta^\ast\omega_n^\ast\, \hat T - 1}{\hat K}
$$

实现为静态纯函数 `AutoTuner::polePlacement(K, T, zeta, wn, Kp, Kd)`，便于独立单测。

**实现细节**：

1. **除零保护**（已关闭，P6 整改已落地）：|K| < 1e-6 或 |T| < 1e-6（含非有限值）时 `polePlacement` 返回 false、不产生增益——Kp=0 意味着开环，直接送给 PD 是危险的；调用方（`applyEstimate_()`）在 false 时保持原增益。
2. **Kd 正性约束**：公式在 $2\zeta^\ast\omega_n^\ast \hat T < 1$ 时给出负 Kd（例如 ζ*=0.85、ωn*=0.2 时要求 T > 2.94 s）。小 T 快响应船本就不需要微分补偿，但负 Kd 会反向放大振荡，**必须 clamp 到 Kd ≥ 0** 并记录告警。
3. **ζ*/ωn* 按船速分段**（设计文档 §3.10.4 表）：< 4 kn 取 (0.9, 0.15)、4~10 kn 取 (0.85, 0.20)、10~18 kn 取 (0.85, 0.25)、18~25 kn 取 (0.90, 0.20)。当前 Params 只有单组 zeta/wn，分段逻辑由上层在船速变化 > 2 kn 时改写 Params 实现（现状：单组缺省 ζ=0.85/ωn=0.20，船速分段未实装——代码中尚无改写 Params 的上层逻辑，列为后续项）。
4. **验证公式**（与 §3.8 一致，用于监控反算）：

$$
\omega_n = \sqrt{\frac{K_p \hat K}{\hat T}},\qquad
\zeta = \frac{1+K_d \hat K}{2\sqrt{\hat T\,K_p \hat K}}
$$

将 polePlacement 的输出代回，应精确还原 ζ*、ωn*（单测断言，容差 1e-9）。

### 6.4 层 3：ESC 极值搜索

#### 6.4.1 性能指标（ITAE + 控制能耗）

$$
J = \int_0^{T_w} \left(t\,|e(t)| + w_u|\delta(t)| + w_{\dot u}|\dot\delta(t)|\right) dt
$$

- 评估窗口 T_w = 60 s，w_u = 0.01、w_du = 0.005（Params 默认值）。
- 实现为三个定长环形数组（`windowErr_/windowDelta_/windowDDelta_`，P2 整改：无堆分配，容量上限 T_w/dt = 3000 样本）；R1 起 `accumulate()` 为私有，由 `tick()` 每拍推入性能样本并同步做 ESC 因果解调累积。
- **注意**：ITAE 的时间权重 t 以窗口起点为零点。该实现语义是"窗口内 ITAE"：窗口非重叠，每次结算后样本清零重计，因此评估两组增益优劣时窗口天然对齐（每个 ESC 步长评估完整的 60 s 窗口）。

#### 6.4.2 ESC 更新流程

```mermaid
graph LR
    BASE["基线增益 curKp/curKd"] --> PERT["每拍扰动注入（escDither）<br/>a = 5%, ω = 0.05 rad/s<br/>Kp 乘 sin、Kd 乘 cos（正交）"]
    PERT --> RUN["运行 60 s 窗口<br/>tick 每拍 accumulate 采样"]
    RUN --> DEMOD["每拍因果解调<br/>成本增量 → HPF 去直流 → × 本拍载波累积"]
    DEMOD --> JCALC["窗末结算（settleWindow_）<br/>computeJ + 解调归一化 → LPF 平滑梯度"]
    JCALC --> STEP["梯度下降 Kp ← Kp − η·grad<br/>η = 0.02"]
    STEP --> CLAMP["clampUpdate 单次变化 ≤ 10%<br/>（含绝对下限 1e-3 防锁死）"]
    CLAMP --> BASE
```

**实现细节与易错点**：

1. **时间尺度分离**是 ESC 收敛的前提：扰动周期 2π/0.05 ≈ 126 s ≫ 闭环调节时间（≤ 30 s）≫ 控制周期 20 ms。窗口结算（`escStep`）只能按窗口周期（60 s）执行一次。R1 深化后该节拍内收：`tick()` 按 `windowSec/dt` 换算窗口拍数并自维护 `winCounter_`，满窗才调私有 `settleWindow_()`——主循环无需也不应再有外部 60 s 调度器（原 core 的 `escTrigger`/外部触发编排已删除）。
2. **相位错开 90°**：Kp 用 sin(φ)、Kd 用 cos(φ)，两通道扰动正交，解调时互不耦合。
3. **标准 ESC 结构（P11 已落地）**：扰动真实注入增益（每拍叠加 a·sin/cos 载波），每拍做因果解调——成本增量经按控制周期 dt 设计的一阶 HPF 去直流后乘以本拍载波累积；窗末归一化为梯度（ĝ = 2·Σ(y·载波)/(a·N)），再经按 windowSec 计算的 LPF 平滑后积分。旧"简化解调"（dJ×sin 相关、增益窗内恒定）的梯度没有因果来源、被衰减 2~3 个量级，已废弃。
4. **禁用状态短路**：`enabled_ == false` 时 `escDither`/`escStep` 直接返回，增益冻结；`enabled_` 由 `tick()` 每拍按速度门控自维护（§6.4.3）。

#### 6.4.3 触发与去激活

设计文档 §3.10.6 的触发矩阵在 R1 深化后的实现位置——编排已内收进 AutoTuner，上层（`autopilot_core`）不再持有任何节拍计数器或增益副本：

| 触发条件 | 动作 | 实现位置（R1 现状） |
|----------|------|----------|
| 船速变化 > 2 kn | 重算层 2 | 无需专门检测：`tick()` 每拍做周期辨识评估，K/T 估计相对基线漂移超 ±25%（`kReBaselineTol`）时经私有 `applyEstimate_()` 自动重配置并重锚 ESC（P12） |

### 6.5 稳定性监控与回退

四条件全满足才接受新增益（设计文档 §3.10.7）：

```mermaid

    C4 -->|否| REJ
```

**实现细节**：

R1 深化：上图的稳定门在两条私有路径上生效——周期辨识评估与一次性建基线共享 `applyEstimate_()`（通过才 `setBaseline` 并接管增益）；ESC 窗口结算为 `settleWindow_()`（原 `AutopilotCore::escTrigger` 内收，由 `tick()` 满窗自触发），仅在启用且基线已建立时执行，ESC 更新经 `stabilityCheck`（取当前辨识快照 K̂/T̂ 与实测振荡幅值）通过才写入 `curKp_/curKd_`（增益所有权），否则 `revert()` 回退基线。

1. 条件 C4 由 `clampUpdate()` 在更新路径上强制满足（截断而非拒绝），`stabilityCheck()` 实际判定 C1~C3。
2. **振荡幅值检测（P4 已实装，R1 随迁内收）**：`OscillationDetector` 对航向误差 e 做过零结算的峰-峰幅值估计（跨完整周期）；`tick()` 每拍经私有 `accumulate()` 喂入，且仅当航向参考稳定满 30 s（`kOscRefSettleSec`，P12 门控）才喂——参考机动期间的误差摆动是指令响应而非闭环振荡。C3 条件使用实测幅值，不再恒 0。
3. **回退缓存**：设计要求保留最近 3 组验证通过的参数（§3.10.7），当前只有单组 `baselineKp_/baselineKd_`，需扩展为深度 3 的环形缓存，`revert()` 逐级回退。
4. `stabilityCheck` 对 K、T 有 1e-6 防御，K 或 T 无效时直接返回 false（保守拒绝），方向正确。

## 7. 机动序列（ManeuverSequencer）开发

### 7.1 设计依据

设计文档 §4（仅航向条件下的机动功能方案），尤其 §4.2 通用机动调度框架。实现文件：`control/include/maneuver_sequencer.hpp`，依赖 `angle_utils.hpp`。

### 7.2 通用框架：Leg 状态机

所有机动统一抽象为 **航段（Leg）序列**，序列器是一个由触发条件驱动的状态机：

```cpp
struct Leg {
    Mode    mode;       // HEADING（PD 跟踪目标航向）/ RUDDER（固定舵角）
    double  target;     // 目标航向(deg) 或 目标舵角(deg)
    Trigger trigger;    // HEADING_REACHED / TIME / RATE / NONE
    double  threshold;  // 触发阈值：累计航向变化(deg) / 时长(s) / 转向率(deg/s)
    int     next;       // 下一段索引，-1 表示序列结束
};
```

```mermaid
stateDiagram-v2
    [*] --> Idle
    Idle --> LegActive: setLegs(legs) 且非空
    LegActive --> LegActive: 未触发，持续输出当前段指令
    LegActive --> LegActive: 触发且 next 有效，清零累计量切下一段
    LegActive --> Done: 触发且 next == -1
    Done --> Idle: setLegs() 重新装载
    LegActive --> Idle: 操作员中断（上层切模式）
```

每周期 `update(headingAct, rateAct, dt)` 做三件事：**累计状态量 → 判定触发 → 输出当前段指令（并在触发时切段）**。

### 7.3 触发条件的实现细节（本模块核心难点）

#### 7.3.1 累计航向变化量 cumHeading

`HEADING_REACHED` 触发依赖"**带符号的累计航向变化**"而非当前航向与目标的差值：

$$
\text{cumHeading} \leftarrow \text{cumHeading} + \text{angleDiffDeg}(\psi_k,\ \psi_{k-1})
$$

- 每拍取相邻两拍航向的**最小带符号差**再累加，因此可正确表达"累计转过 270°、540°"这类超过一圈的语义——这是 Circles（360°）、Williamson（180°）能实现的关键。
- 逐拍差分要求 **相邻两拍航向变化 < 180°**。50 Hz 采样下即使 30°/s 的极限转向率每拍也只有 0.6°，裕量充足；但若上层以低频（如 1 Hz）调用且转向率高，会发生折叠错误——调用周期必须 ≥ 10 Hz 写入接口约束。
- **首拍基准**：`first_` 标志用当前航向初始化 `lastHeading_`，避免第一拍把 `ψ_act − 0` 误计入累计量。
- **切段清零**：`legElapsed_` 与 `cumHeading_` 在切段时同时清零，每段的阈值都是"本段内"的增量语义。
- 触发判定带**方向敏感**（P12 整改已落地）：`cumHeading·threshold ≥ threshold²`，即累计量必须沿阈值符号方向达到其幅值才切段——反舵后船舶因惯性顺漂、cum 沿旧方向继续增长时不会把航段"预触发"。阈值带符号（与本段舵向一致），对 Williamson 这类先右后左的机动，反向操舵段阈值为负，语义为"本段内累计净变化量"（见 §7.4.2 的参数推导）。

#### 7.3.2 三类触发对比

| Trigger | 判定式 | 适用 | 注意 |
|---------|--------|------|------|
| HEADING_REACHED | cum·threshold ≥ threshold²（方向敏感，P12） | 转向段 | 增量语义，切段清零；阈值符号须与本段舵向一致 |
| TIME | legElapsed ≥ threshold | 直航定时段（Cloverleaf/Search） | 精度受 dt 粒度限制 |
| RATE | abs(rateAct) ≤ threshold | "转向率衰减到位"类收尾段 | 阈值过小会因噪声永不触发，建议 ≥ 0.5°/s |
| NONE | 永不触发 | 末段长期保持（如 Williamson Leg3） | 由操作员或上层退出 |

### 7.4 六种预置机动开发

#### 7.4.1 总览

| 机动 | 工厂函数 | 段数 | 模式组合 | 可行性（§4.1） |
|------|----------|------|----------|----------------|
| Circles | `circles(dCmd, totalDeg)` | 1 | RUDDER | 完全可行 |
| Williamson | `williamson(psi0, dMax)` | 3 | RUDDER×2 + HEADING | 完全可行 |
| U-Turn | `uTurn(psi0, right)` | 2 | RUDDER + HEADING | 完全可行 |
| Zigzag | `zigzag(psi0, dz, phiz, N, returnToStart)` | 2N（+1 保持段） | RUDDER（+HEADING） | 完全可行 |

#### 7.4.2 Williamson Turn（重点机动）

人落水紧急返点机动，三段式（设计文档 §4.4）：

```mermaid
graph TD
    S["起始航向 ψ0"] --> L1["Leg0: RUDDER +25°"]
    L1 --> T1{"cumHeading ≥ +60° ?<br/>（阈值 +60°，方向敏感 P12）"}
    T1 -->|是 清零切段| L2["Leg1: RUDDER −25°"]
    L2 --> T2{"cumHeading ≤ −180° ?<br/>（阈值 −180°，方向敏感 P12）"}
    T2 -->|是 清零切段| L3["Leg2: HEADING 跟踪 ψ0+180°"]
    L3 --> HOLD["NONE 触发：长期保持<br/>由操作员退出"]
```

**参数推导细节**：Leg1 的阈值 −180°（带符号 P12，与本段左转舵向一致；判定式 cum·threshold ≥ threshold²，见 §7.3.1）是"本段内累计净变化 180°"。Leg1 起点航向 ≈ ψ0+60°（右转后），反向左转过程中 cumHeading 从 0 向负方向增长，累计 −180° 时航向 ≈ ψ0−120°；此时切入 Leg2 的 PD 跟踪 ψ0+180°（= ψ0−180°），剩余约 60° 由 PD 闭环收尾。段间衔接的超调由海试标定 dMax（缺省 +25° 而非满舵 35°，留出修正裕量）。

#### 7.4.3 Zigzag（Z 形，兼作辨识激励）

2N 段全 RUDDER 序列，±δ_z 交替、每段以带符号阈值 ±φ_z 方向敏感触发（P12：阈值符号随本段舵向，§7.3.1）。工程上它同时是 §5 Z 形试验的**激励发生器**：执行 `zigzag(psi0, 10, 10, 5)` 并同步记录 δ(t)、r(t)，即得到 §3.9.4 要求的辨识数据集。

#### 7.4.4 Circles / U-Turn

- Circles：单段 RUDDER（缺省 +15°），阈值 totalDeg=360°。设计文档 §4.3 的"转向率闭环"方案在当前版本以**恒舵角等效**实现（简化合理：Nomoto 稳态下恒舵角即恒转向率）；若海试发现风流下圆度不佳，升级为转向率外环。
- U-Turn：两段式——RUDDER 恒舵角转向段（转满 180°）+ HEADING 保持段跟踪 ψ0±180°，转向方向由 `right` 参数指定。P7 整改已落地（§10.5-P7 已关闭）：转向段改 RUDDER 后方向由舵角符号强制，不再受旧单段 HEADING 实现的缺陷影响（PD 沿最短路径转向，target 恰好 ±180° 时方向取决于误差符号的数值噪声）。完成判据（设计 §4.5：|e|<1° 持续 2 s）当前依赖 NONE 触发 + 上层判断，需上层实现该判据。

#### 7.4.5 Cloverleaf / Search（开环机动）

两者均为直航段（HEADING + TIME 触发）与转向段（RUDDER 恒舵角）交替，属开环机动（无位置闭合，漂移不可消除，设计 §4.7/§4.8 已声明风险）。

**历史缺陷（§10.5-P7，已关闭）**：旧实现转向段使用 `Mode::HEADING` + `HEADING_REACHED` 阈值 270°（Cloverleaf）/ 90°（Search），但 PD 跟踪目标航向时走**最短路径**：+270° 的目标等价于 −90°，实际只会累计约 90°，`abs(cumHeading) ≥ 270°` 永不满足，序列卡死。P7 整改按方案 A 落地：

- 方案 A（已采用）：转向段改为 RUDDER 恒舵角（同 Williamson），达到累计角度后切 HEADING 直航段收尾。现状补充：Cloverleaf 四个转向段同向（`dMax` 符号决定左/右旋四叶，总航向变化 4×270° 净回 ψ0，几何闭合）；HEADING_REACHED 触发带方向敏感（P12：`cumHeading` 须沿阈值符号方向达到幅值才切段，防反舵顺漂预触发）。
- 方案 B（未采用）：将 270° 转向拆为 3 个 90° HEADING 子段，每段最短路径方向与期望一致。

#### 7.4.6 与 PD 控制器的指令衔接

```mermaid
graph LR
    SEQ["ManeuverSequencer::update"] --> CMD{"Cmd.isHeading ?"}
    CMD -->|"是"| PD["headingRef = cmd.heading<br/>rudder = pd.update(ref, act)"]
    CMD -->|"否"| DIRECT["rudder = cmd.rudder<br/>（仍须经限幅/舵速约束）"]
```

**注意**：RUDDER 段旁路了 PD 控制律，但**不得旁路安全限幅**——恒舵角指令仍须经舵角/舵速限幅（设计 §4.10）。已落地（P7 整改，§10.5-P7 已关闭）：`autopilot_core` 中 RUDDER 段经 `pd_.saturate(cmd.rudder)` 施加幅值/舵速限幅。

### 8.4 CRC 与版本机制

- CRC32 采用 IEEE 802.3 多项式 `0xEDB88320`，逐 bit 实现（无查找表，牺牲速度换 ROM 空间，仅在保存/加载时调用，可接受）。
- `save()`：版本号 +1 → 计算 CRC → 序列化写入；`load()`：读取 → CRC 校验，失败返回 false 由上层加载默认安全参数并告警（设计 §3.9.8）。
- **人工标定优先级高于自动优化**（设计 §3.10.8）：人工标定写入后，AutoTuner 的基线（`setBaseline`）必须重置为标定值。

上电加载流程：

```mermaid
graph TD
    BOOT["上电"] --> LOAD["ParamStore::load"]
    LOAD --> CRCOK{"读取成功且 CRC 通过?"}
    CRCOK -->|是| RANGE{"参数物理范围检查<br/>K ∈ (0,2], T ∈ [1,60], Kp/Kd > 0 ?"}
    CRCOK -->|否| DEF["加载默认安全参数<br/>Kp=1.0 Kd=0.5 + 告警"]
    RANGE -->|通过| APPLY["应用参数<br/>PD/调度表/AutoTuner 基线"]
    RANGE -->|不通过| DEF
    DEF --> APPLY2["以保守参数运行<br/>禁用自动优化"]
```

（范围检查为增补要求，P8 已实装 `validateRange()`——K∈(0,2]、T∈[1,60]、Kp>0、Kd≥0、舵速限幅 1~30°/s 等，由上层在 `load()` 成功后调用；`load()` 本身仍只做 CRC 校验，§10.5-P8 已关闭。）

### 8.5 序列化实现的风险与整改

旧实现 `serialize()` 用 `memcpy(this)` 截取 `sizeof(ControlParams) − 4` 字节，存在三个问题（§10.5-P8，**已关闭——P8 整改已落地**，逐字段显式小端序列化）：

1. **CRC 字段自包含**：`ControlParams` 按 8 字节对齐后 crc 位于截取范围内，`updateCrc()` 计算摘要时包含旧 crc 值、写入新值后 `verifyCrc()` 重算的摘要即与存储值不符——**save 后立即 load 会校验失败**。整改（已落地）：序列化范围显式排除 crc 字段（逐字段序列化，crc 追加在 payload 末尾）。
2. **依赖结构体内存布局**：填充字节内容未定义，同一份参数两次序列化可能产生不同 CRC；跨编译器/ABI 不可移植。整改（已落地）：逐字段小端序列化。
3. **load 读取长度**与 save 写入长度不一致（`sizeof` vs `sizeof−4+4` 的布局差异），依赖填充巧合。整改后统一为显式格式（现状）：`[8×double 区块A/B/C][version u32][timestamp u32][schedCount u32][区块 D 调度表逐点]` + 末尾 crc u32，长度随调度表条数变化。

## 9. 核心集成与主循环开发

### 9.1 设计依据

设计文档 §5（定位与控制联合工作流）：§5.1 主循环、§5.2 模式切换、§5.3 定位失效降级、§5.4 数据流时序。实现文件：`control/include/autopilot_core.hpp`。

### 9.2 集成接口

`AutopilotCore::step(SensorInput, dt) → 目标舵角` 是算法层与 BSP 层唯一的运行时边界：

```cpp
struct SensorInput {
    double headingDeg;   // AHRS 艏向（已融合 GNSS 校正后的值）
    double rateDegS;     // AHRS 转向率
    double rudderDeg;    // 舵角反馈
    double speedKn;      // 船速（GNSS/计程仪）
    int    seaState;     // 海况 0..3（人工设定或估计）
};
```

**边界约定**：航向融合（"AHRS 高频 + GNSS 校正"，设计 §5.1）与传感器有效性判断在 BSP/融合层完成，`headingDeg` 进入算法层时已是可信值；定位失效降级（设计 §5.3）表现为上层切换模式，算法层不感知 GNSS 状态。

**辅助接口（R1 深化）**：调参器参数经 `setTunerParams(const AutoTuner::Params&)` 整组注入（替代旧的 mutable 引用接口）。自动优化在 core 内只剩"每拍转发"：全部编排（速度门控/辨识评估/ESC 窗口/稳定门/回退/扰动）收在 `AutoTuner::tick()` 内部（§6.2、§9.4）；辨识试验收官 `finalizeIdentTrial` 缩为一行 `tuner_.establishBaseline(idSnapshot())` 映射 OK/FAILED；`setMode` 切出到 MANUAL/HOLD 时调 `tuner_.suspend()`（清测量状态、保留基线）。

### 9.3 模式状态机


各模式输出语义：

| 模式 | 输出 | 说明 |
|------|------|------|

### 9.7 实时性预算

50 Hz 周期内算法层最坏执行时间预算 < 2 ms（周期的 10%）：

| 环节 | 预算 | 依据 |
|------|------|------|
| 增益调度查表 | < 10 μs | 14 条线性扫描 |
| RLS 更新（触发拍） | < 50 μs | 2×2 矩阵定长运算 |
| 极点配置 + 稳定性检查 | < 10 μs | 纯标量运算 |
| accumulate + 队列维护 | < 20 μs | 固定容量环形数组（P2 已落地，编译期容量 3000，主循环无堆分配） |
| PD update | < 10 μs | 标量运算 |
| 合计 | **< 100 μs** | 裕量 20 倍 |

`computeJ()`（3000 样本遍历）只在窗口结算拍执行（每 60 s 一拍；R1 起结算在 `tick()` 内完成，计入该拍主循环开销，预算仍有充足裕量）。

### 10.2 闭环仿真验证（V 模型右侧第 2 级）

仿真被控对象（PC 端，与单测同工程）：

$$
\dot r = \frac{K\delta_{\text{act}} - r}{T},\qquad
\dot\delta_{\text{act}} = \mathrm{clip}\left(\frac{\delta_{\text{cmd}} - \delta_{\text{act}}}{\tau_s},\ \pm\dot\delta_{\max}\right),\qquad
\dot\psi = r
$$

- 舵机一阶惯性 τ_s = 0.3 s + 舵速物理限幅；
- 量测噪声：ψ 加 σ = 0.2° 白噪声，r 加 σ = 0.1°/s；
- 干扰：恒值风致力矩（等效舵角 2°）+ 0.1 Hz 波浪扰动。

验证矩阵（每项跑典型船参数 K=0.2/T=8 与边界参数 K=0.5/T=3、K=0.1/T=20）：

| 验证项 | 判据（§1.5 / 设计 §3.9.6） |
|--------|---------------------------|
| 30° 航向阶跃 | 超调 ≤ 10%，5% 调节时间 ≤ 30 s |
| 航向保持（带干扰） | 稳态误差 ≤ 1°，操舵频次 ≤ 6 次/分钟 |
| 增益调度切换 | 船速斜坡 2 → 24 kn，无输出跳变 > 1° |
| RLS + 极点配置闭环 | 从偏差 50% 的初始 K/T 出发，10 min 内恢复设计指标 |
| ESC 长期运行 | 2 h 仿真 J 无发散，增益始终在界内 |

### 11.2 可视化调参总流程

调参按 **SIL 仿真 → HIL 半实物 → 海试** 三阶段递进，参数只能"向上带"（上一阶段的结果作为下一阶段初值），不允许跳级：

```mermaid
graph LR
    SIL["阶段 1 SIL 仿真调参<br/>内置仿真器，无风险<br/>粗调：增益量级与调度表"] --> HIL2["阶段 2 HIL 调参<br/>WebSocket 连 ECU<br/>细调：真实时序与量化效应"]
    HIL2 --> SEA["阶段 3 海试调参<br/>场地 D1~D2，联锁保护<br/>微调：±10% 单变量步进"]
    SEA -->|结果回灌| SIL
```

每一轮调参遵循统一的闭环（任一阶段通用）：

```mermaid
graph TD
    W["1 设定工况<br/>船速 / 海况 /（仿真时）K/T"] --> P["2 修改参数<br/>输入框或滑块，单变量原则"]
    P --> X["3 注入激励<br/>航向阶跃 / 机动序列 / 保持观察"]
    X --> C["4 采集响应<br/>曲线 + 指标面板（U1）"]
    C --> J1{"5 判据评估<br/>§1.5 指标 PASS ?"}
    J1 -->|否| A["分析方向：超调大增 Kd<br/>响应慢增 Kp、抖动增 τ/死区"]
    A --> P
    J1 -->|是| V["6 跨工况复验<br/>至少 3 个船速点 × 2 个海况"]
    V --> S["7 固化与记录<br/>下发 ECU ParamStore + 会话日志（U6）"]
```

**单变量原则**：每轮只改一个参数（与设计文档 §3.9.7 一致，海试阶段步长 ±10%）；改多个参数后无法归因，会话日志（U6）按次记录以便回滚。

| 超调量 | (max(ψ) − ψ_ref) / 阶跃幅值 × 100% | ≤ 10% |
| 5% 调节时间 | 误差最后一次进入 ±5%·阶跃幅值 的时刻 | ≤ 30 s |
| 稳态误差 1σ | 进入稳态后误差标准差 | ≤ 1° |
| 操舵频次 | rudderCmd 变化方向翻转次数 / 分钟（幅值 > 量化步长才计） | ≤ 6 次/min |
| ITAE J | 复用 `computeJ` 同款公式 | 趋势参考 |

#### U2 一键阶跃试验

按固定脚本执行，消除人工操作差异：稳定保持 10 s（误差 1σ < 0.5° 才继续）→ 施加 +30° 阶跃 → 采集 60 s → 施加 −30° 回程 → 采集 60 s → 自动弹出 U1 报告并可导出。左右双向各一次，检查不对称性（不对称提示舵零位偏差，联动 §8 标定）。

#### U3 参数扫描与 A/B 对比

- **网格扫描**（仅 SIL 模式）：设定 Kp ∈ [a,b]×N 点、Kd ∈ [c,d]×M 点，逐点静默仿真固定场景（30° 阶跃 + 60 s 保持），输出 J 的 N×M 热力图，点击热力图单元格即载入该组参数。为 §11.3.1 手动整定提供初值定位。
- **A/B 对比**：保存当前响应为基线曲线（灰色叠加显示），改参后新响应与基线同屏对比，指标面板双列显示差值。

#### U4 数据回放

导入 §10.4 海试记录或 UI 自身导出的 CSV/JSON，以可调倍速重放曲线并重算 U1 指标。用途：海试当晚复盘、缺陷回归（如 §7.4.5 序列卡死的现场数据回放）、向评审提供证据曲线。

#### U5 ζ-ωn 约束平面

以 ζ 为横轴、ωn 为纵轴绘制稳定性监控（§6.5）的可视化：

- 画出约束边界 ζ = 0.6（左禁区）与 ωn = 0.5 rad/s（上禁区）；
- 实时描点 (ζ̂, ω̂n)（由当前 Kp/Kd 与 K̂/T̂ 按 §6.3 验证公式反算），带 60 s 轨迹尾迹；
- 目标点 (ζ*, ωn*) 用十字标注。点落入禁区即红色告警，与 `stabilityCheck` 拒绝行为一致——调参者可在增益被拒绝**之前**直观看到趋势。

#### U6 调参会话日志与回滚

每次"应用参数"自动追加一条会话记录：

```json
{ "ts": 1722310000, "scope": "pd", "old": {"Kp":1.5,"Kd":0.6}, "new": {"Kp":1.65,"Kd":0.6},
  "metrics": {"overshoot":8.2,"ts5":22.1,"ess":0.6,"freq":4.1}, "stage": "HIL" }
```

- 侧栏时间线展示，任意条目一键恢复该组参数（含下发 ECU）；

#### U7 在线调参安全联锁（ECU 已连接时强制生效）

| 联锁项 | 规则 | 依据 |

## 12. 实船调试接口开发

### 12.1 设计依据与定位

实船调试/标定需要绕开 `tick()` 的固定编排（§6.2、§9.4），对单一环节做激励—观测：只验极点配置数值、只打一拍载波看执行器响应、只喂误差看振荡检测读数、只把当前窗口的 J 读出来。为此在 M3 之后补充交付**实船调试接口**，交付物一览：

| 交付物 | 文件 | 角色 |
|--------|------|------|
| 调试接口门面 | `control/include/tuner_debug_api.hpp` | `TunerDebugApi` 把 `AutoTuner` 的公有动作与私有机制全部摊平为独立方法，每个方法对应一个且仅一个功能，互不影响、任意顺序调用 |
| 命令行工具 | `control/tools/tuner_debug_cli.cpp` | 逐行命令封装 `ar_tuner_debug`，可经 ssh/串口终端在船上直接使用 |
| 实时监控脚本 | `control/tools/tuner_debug_monitor.py` | 驱动 CLI 轮询 `status`，matplotlib 实时曲线 + 命令转发 + CSV 落盘 |
| 端到端验收脚本 | `control/tools/tuner_debug_accept.py` | 驱动 CLI 对 9 个功能组 49 项断言，退出码可直接接入 CI |
| 单元测试 | `control/tests/test_tuner_debug_api.cpp` | 13 个用例，纳入 §10.1 测试体系（见 §12.5） |

实现机制：`AutoTuner` 仅增加一行 `friend class TunerDebugApi` 声明，调试方法直接调用同一批私有函数（同一参数、同一行为），**不改动任何在线路径**。使用约束（与实船安全直接相关，已写入头文件注释）：

1. 本接口只用于调试/标定，**不得接入正常航行控制回路**——`force*` 系列旁路稳定门，正常路径的安全保证全部失效；
2. 除 `force*` 系列外，其余方法与其在 `tick()` 内部的行为逐字一致，观测结果可代表在线行为（有单测保证，§12.5）；
3. 所有方法均无堆分配、无 IO，可在 ECU 上经串行/以太网命令通道驱动。

### 12.2 构建：AR_BUILD_TOOLS 与编译产物

`control/CMakeLists.txt` 新增开关，与 `AR_BUILD_TESTS`/`AR_BUILD_SIM` 并列、默认开启：

```cmake
option(AR_BUILD_TOOLS "Build debug/commissioning tools" ON)
```

`AR_BUILD_TOOLS=ON` 时 `add_subdirectory(tools)`，编译产物为单一可执行文件 **`build/tools/ar_tuner_debug`**（仅链接 header-only 的 `ar_headers` INTERFACE 库，无第三方依赖）：

```bash
cd control/build && cmake .. && make ar_tuner_debug   # 默认即构建
cmake -DAR_BUILD_TOOLS=OFF ..                         # 裁剪发布镜像时可整体关掉
```

### 12.3 ar_tuner_debug 基本用法

**交互模型**：每行一条命令，每条命令恰好调用 `TunerDebugApi` 的一个功能，可任意顺序单独调用。输出协议：成功 `OK ...`、失败/拒绝 `ERR <原因>`；观测类命令输出 `key=value` 序列。启动时按 `isatty` 判别——交互终端打印横幅与 `> ` 提示符；脚本/管道模式输出保持纯净（无横幅无提示符），上位机逐行解析：

```bash
./build/tools/ar_tuner_debug              # 交互（可经 ssh/串口终端）
./build/tools/ar_tuner_debug < cmds.txt   # 脚本模式
```

典型会话（行尾注释为输出要点）：

```text
> pole 0.2 8                     # OK Kp=1.600000 Kd=8.600000（默认 ζ=0.85 ωn=0.2）
> check 0.2 8 1.6 8.6 0          # OK pass=1（稳定门四条件判定）
> baseline 0.2 8                 # OK established=1（一次性建基线）
> forceenabled 1                 # 单环节调试前置：绕开速度门控
> dither 1.6 8.6                 # OK Kp=... Kd=...（打一拍载波并推进相位）
> accum 1.0 2.0 1                # OK（成本累积 + 振荡检测 + 因果解调）
> step 1.6 8.6                   # OK Kp=... Kd=...（窗末梯度结算）
> settle 1 0.2 8                 # OK curKp=... curKd=...（窗末裁决：结算+稳定门+接受/回退）
> status                         # OK curKp=... osc=...（全量快照）
> quit
```

命令分组（`help` 命令可查全表）：

| 组 | 命令 | 对应 TunerDebugApi 方法 |
|---|---|---|
| 观测 | `status` / `j` / `osc` | `snapshot()` / `currentJ()` / `oscAmplitude()` |
| 观测（参数） | `params` / `setparam <名称> <值>` | `params()` / `setParams()` |
| 层 2 | `pole` / `check` / `baseline` / `eval` | `polePlacement` / `stabilityCheck` / `establishBaseline` / `evaluateEstimate` |
| ESC | `dither` / `accum` / `step` / `settle` / `clamp` | `ditherOnce` / `accumulateOnce` / `escStepOnce` / `settleWindowOnce` / `clampUpdate` |
| 振荡 | `oscfeed` / `oscreset` | `oscFeed` / `oscReset` |
| 生命周期 | `revert` / `rebase` / `suspend` / `reset` | `revertToBaseline` / `rebaseEsc` / `suspend` / `reset` |
| 主流程 | `tick` | `tick()`（与在线路径同一函数） |
| 强制注入 | `forcegains` / `forcebase` / `forcephase` / `forcegrad` / `forceenabled` | `forceGains` / `forceBaseline` / `forceEscPhase` / `forceGradient` / `forceEnabled` |

实现要点与易错点：

1. **可选参数缺省**：`pole` 的 ζ/ωn 缺省 0.85/0.20；`settle [valid K T]` 三个参数全可选，缺省 `valid=1` + 典型船估计 K=0.2/T=8（`K_SHIP_DEFAULT`/`T_SHIP_DEFAULT`）；`tick` 的辨识快照 4 参数可选（缺省 `excited=0 valid=0`）。
2. **`setparam` 的复位语义**：改写单个参数走 `setParams()`，内部复位调参器——**基线一并清空**（`reset` 不恢复 Params，验收脚本组 6 据此显式恢复默认值，避免参数跨组泄漏）。可选参数名共 17 个：`zeta wn escAmp escFreq escStep hpfTau lpfTau wU wDu maxUpdateFrac absMinUpdate zetaMin wnMax oscMax highSpeedKn windowSec dt`。
3. **单环节调试前置 `forceenabled 1`**：`dither`/`accum`/`step` 依赖 `enabled_`，单独调试时先用 `forceenabled` 置位绕开速度门控，否则命令空转（验收脚本组 3 断言了"未开 enabled 时 dither 不动"）。
4. **`forcebase` 的副作用**：`forceBaseline` 不记录 `baseK_/baseT_`（保持 0），此后 `driftGate=true` 的漂移判据会把任何 K/T 视为超阈值漂移（分母走 floor），下一次评估恒重基线——保守的安全方向，但调用方应知情。
5. **防御式解析**：参数不足、未知参数名、未知命令一律 `ERR` 并附用法提示，不崩溃、不改变调参器状态（验收组 9 覆盖）。

### 12.4 监控与验收脚本（tools/*.py）

两脚本与既有仿真可视化工具同层，依赖收敛在 `control/tools/requirements.txt`（`matplotlib>=3.5`、`numpy>=1.20`）：

```bash
pip install -r tools/requirements.txt    # 或 apt 安装 python3-matplotlib python3-numpy
```

**`tuner_debug_monitor.py`——调试参数实时监控**：驱动 `ar_tuner_debug` 进程（管道请求—响应，线程安全），按固定周期下发 `status` 并解析 `key=value`，用 matplotlib 滚动绘制 4 个子图：增益（当前实线/基线虚线）、ESC 梯度估计（LPF 后）、窗口代价 lastJ、实测振荡 + 载波相位。监控期间在终端输入的任何命令原样转发给 CLI（回显打印），即"一面看曲线、一面做单环节调试"。

```bash
python3 tools/tuner_debug_monitor.py            # 交互监控（默认找 ../build/tools/ar_tuner_debug）
python3 tools/tuner_debug_monitor.py --demo     # 内置激励演示，无实船即可自检监控链路
PLOT_SIM_AGG=1 python3 tools/tuner_debug_monitor.py --demo --duration 15 --out out/monitor.png  # 无 GUI 冒烟/归档
```

| 选项 | 含义 | 默认 |
|---|---|---|
| `--exe PATH` | `ar_tuner_debug` 可执行文件路径 | `../build/tools/ar_tuner_debug`（相对脚本位置） |
| `--interval S` | `status` 轮询周期 (s) | 0.1 |
| `--window S` | 曲线滚动时间窗 (s) | 60 |
| `--demo` | 内置激励序列（`baseline 0.2 8` → `forceenabled 1` → ±2° 方波误差 `accum` + `dither`，每 6 s 一次 `settle`） | 关 |
| `--log CSV` | `status` 快照追加写入 CSV（t + 14 个监控字段） | 关 |
| `--duration S` / `--out PNG` | 固定时长后保存图片退出（无 GUI 冒烟用） | 关 |

实现注意：交互刷新用 `FuncAnimation`，**必须持有引用**（`self._anim`），否则动画对象被 GC、窗口空白（matplotlib 官方陷阱）；监控字段名以 CLI `status` 实际输出的 `key=value` 为准（如基线为 `baseKp`/`baseKd`）。监控器与被调试的调参器是同一进程内实例（经管道请求—响应），船上使用时 `--exe` 指向船上命令通道的封装即可。

**`tuner_debug_accept.py`——端到端验收**：驱动 CLI 对 9 个功能组逐条断言预期输出，共 **49 项**（每条命令的预期数值均经手工核算）。与 `test_tuner_debug_api.cpp` 互补——单测测 API 层，验收脚本测 CLI 端到端（含参数解析与输出协议）：

```bash
python3 tools/tuner_debug_accept.py [--exe PATH]   # 全绿输出 "49 PASS / 0 FAIL"
```

退出码全 PASS 为 0、任一 FAIL 为 1，可直接接入 CI。9 个组：①极点配置/稳定门 ②基线管理 ③ESC 各环节 ④振荡检测 ⑤回退/重锚/生命周期 ⑥参数读写 ⑦强制注入 ⑧tick 主流程编排 ⑨输出协议健壮性。

### 12.5 单元测试纳入测试体系

`control/tests/test_tuner_debug_api.cpp`（13 个用例）按 §10.1 的既有约定纳入：加入 `control/tests/CMakeLists.txt` 的 `AR_TEST_SOURCES` 列表即可，`foreach` 循环自动为其生成独立可执行目标（链接 `ar_headers` + `GTest::gtest_main`）并经 `gtest_discover_tests` 注册（含 ASan/LSan 环境变量），随 `AR_BUILD_TESTS`（默认 ON）与其余测试文件一起构建运行，Release + ASan 双工具链同测。

13 个用例中有两条关键保证，是全接口可信度的基石：

| 用例 | 保证 |
|------|------|
| `TickThroughApiMatchesDirectTick` | 经 API 的 `tick()` 与直接调 `AutoTuner::tick()` 连续 50 拍输出**逐位一致**（DOUBLE_EQ）——调试接口观测即在线行为 |
| `ForceGainsBypassesGate_DebugOnly` | 必不过稳定门的增益（Kp<0）经 `forceGains` 照样写入，且基线未被污染——`force*` 确属旁路，且旁路范围受控 |

其余用例逐组覆盖：透传一致性（pole/check）、基线建立与快照一致、`evaluateEstimate` 漂移门语义（±25% 阈值内外）、dither 门控与相位推进、accumulate/escStep 独立可调用、clamp 比例上限与绝对下限（P11 锁死回归）、振荡喂入/清零、revert/rebase/suspend 语义、`settleWindowOnce` 接受与回退双路径、`setParams` 复位语义。

### 12.6 典型开发/调试工作流

**开发期（PC，无实船）**——改动 AutoTuner 内部机制或调试接口后的回归顺序：

```mermaid
graph LR
    EDIT["改动 auto_tuner.hpp /<br/>tuner_debug_api.hpp"] --> UT["test_tuner_debug_api<br/>API 层单测（13 用例）"]
    UT --> E2E["tuner_debug_accept.py<br/>CLI 端到端（49 断言，退出码接 CI）"]
    E2E --> MON["tuner_debug_monitor.py --demo<br/>监控链路自检 + 目视确认曲线"]
```

**实船调试**——以"单环节激励—观测"为主线，以全量快照为遥测：

```mermaid
graph TD
    SSH["ssh/串口终端连接船上 ECU"] --> CLI["ar_tuner_debug<br/>（或船上命令通道封装）"]
    CLI --> PRE["前置：forceenabled 1（绕开速度门控）"]
    PRE --> ACT["逐环节激励：pole / check / baseline / eval<br/>dither / accum / step / settle / oscfeed"]
    ACT --> OBS["观测：status / j / osc / params"]
    OBS --> LOOP{"行为符合预期 ?"}
    LOOP -->|否| INJ["force* 注入构造边界场景复现"]
    INJ --> ACT
    LOOP -->|是| WATCH["tuner_debug_monitor.py --exe 长期监控<br/>+ --log 落盘 CSV"]
```

操作要点：

1. **先验收后调试**：上船先跑 `tuner_debug_accept.py`，确认船上构建的 CLI 行为与 PC 逐条一致；
2. **改参即重来**：任何 `setparam` 都会复位调参器状态（基线清空），改完须重新 `baseline` 建基线再观察 ESC；
3. **落盘复盘**：`--log` 落盘的 CSV 与 `docs/实船调试接口调用文档.md` 的行协议字段一致，事后可按 §11-U4 的回放思路复查；
4. **红线**：`force*` 仅限受控试验（如执行器响应试验用 `forcegains` 注入指定增益）；正常航行控制回路严禁接入本接口（§12.1 约束 1）。
