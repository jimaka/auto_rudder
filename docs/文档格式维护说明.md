## 检查和自动修复

在项目根目录执行：

```bash
# 只检查，不改写文档；发现问题时返回非零退出码
python3 scripts/format_docs.py --check

# 自动修复可安全处理的空行、文件末尾换行、表格公式/代码竖线
python3 scripts/format_docs.py --fix

# 将当前检查结果输出为 JSON
python3 scripts/format_docs.py --check --report /tmp/auto-rudder-doc-format.json

# 文档格式与导出工具的回归测试
python3 -m unittest scripts.test_doc_format -v

# 使用本地 Chrome、KaTeX、Mermaid 检查公式和流程图
python3 scripts/check_doc_render.py --report /tmp/auto-rudder-doc-render.json
```

检查器同时检查表格列数、本地图片/文件引用、Markdown 标题锚点和代码围栏闭合。缺失目标、失效锚点和 Mermaid 语法需要根据实际含义人工修复，工具不会猜测目标或改写流程。

脚本依赖 Python 3 和项目现用的 `markdown-it-py`，文件清单由 `rg` 获取。渲染检查及 PDF 导出还需要 `google-chrome`。KaTeX/Mermaid 优先使用本机已有资源；可通过 `MD2PDF_ASSET_DIR` 指定包含 `katex/`、`mermaid/` 子目录的资源目录。没有本地资源时会使用导出脚本配置的 CDN，离线环境下应先配置本地资源。

## 更新导出文档

```bash
# 只重导出 pdf_output/ 中已经存在、且有匹配 Markdown 的文件
python3 md2pdf.py --existing

# 导出指定文档
python3 md2pdf.py docs/ESC减参方案实施阶段计划.md

# 工程说明 HTML
python3 docs/project_overview/render_html.py

# 架构索引、调用图谱和架构 HTML
python3 docs/architecture/generate_call_atlas.py
python3 docs/architecture/render_document.py
python3 docs/architecture/validate_artifacts.py

# ESC 实施计划的插图、HTML 及引用检查
python3 docs/esc_parameter_reduction/implementation/build_document.py
```

PDF 先写入临时目录，确认浏览器已完成公式、流程图、图片及字体加载后才替换原文件。渲染失败或超时会保留旧 PDF，并返回失败状态。不会自动修改原始论文或 PPT 导出的 PDF。

架构图谱重新扫描后，主说明文档中的汇总数字也需与 `architecture/functions.json` 的 `stats` 对齐。图谱源码快照的更新不代表执行了控制算法或测试了控制效果。
